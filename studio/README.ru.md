# AI PDF — установка на сервер

Редактор PDF в браузере: просмотр и поиск, комментарии, страницы (повернуть, удалить,
вставить, извлечь, разделить, объединить, упорядочить), водяные знаки, колонтитулы, нумерация, сжатие, пароль, скрытие
данных, формы, заполнение и подпись, экспорт в картинки, текст и Word. Со встроенным помощником на вашей локальной модели
и файлами на вашем сервере. На сервере нужны только **nginx + PHP + Ollama**. Ничего компилировать не нужно.
Всё загружается из папки приложения: интернет и сторонние сайты не нужны.

Acrobat — товарный знак Adobe. AI PDF не связан с Adobe и работает с файлами в её форматах.

## Установка

1. **Скачайте сборку**: GitHub → `ai-acrobat` → **Releases** → верхняя «Сборка N — дата» → `ai-acrobat-build-N-ГГГГ-ММ-ДД.zip`.
2. **Распакуйте** и положите папку `ai-acrobat` на сервер рядом с остальными приложениями (`/app/src/ai-acrobat/`).
   Помощник и хранилище сами найдут ваш `auth.php` и через него — `config.php`, `.env`, адрес Ollama и модель.
3. **Папка для файлов создаётся сама**: `storage/ai-acrobat` рядом с корнем сайта (на диске `/var/www/dwr/storage/ai-acrobat`).
   Проверка: `https://ваш-домен/ai-acrobat/api/files.php` → `{"ok":true,…}`.
4. **nginx** — готовые блоки в `nginx.conf.example` (если они уже добавлены для других AI-приложений, второй раз не нужно).
5. **Откройте** `https://ваш-домен/ai-acrobat/`.

**Обновление**: залейте новую папку поверх старой — любой программой. Каждая сборка лежит в своей папке `b/<номер>/`,
`index.php` открывает самую новую, поэтому файлы разных сборок не смешаются. Ваш `studio/config.js` и файлы пользователей
не трогаются. Старые папки `b/…` можно удалить.

## Файлы

- **Ctrl+S** сохраняет PDF в «Мои файлы» на сервере (значок папки в панели помощника). Первый раз спросит имя.
- **Мои файлы**: список, поиск, открыть, переименовать, удалить (в корзину `.trash`), «С компьютера…» — открыть PDF с компьютера.
- У каждого пользователя своя папка. Если сохранить не удалось (нет связи), копия остаётся в браузере.

## Помощник

- **Совет** — объясняет, где что найти; читает документ: пересказывает, находит сроки и суммы, проверяет договор.
  Сканы без текста читает по снимку экрана (нужна модель, которая принимает картинки).
- **Сделай** — сам поворачивает, удаляет, вставляет страницы, сжимает файл, открывает нужные окна (водяной знак,
  нумерация, пароль) и говорит, что в них выбрать. Удаление страниц и снятие защиты — только после вашего «Разрешить».
- **Быстрые задачи** (значок с квадратиками): частые действия в одно нажатие и готовые просьбы помощнику.
- **Быстрая строка — Ctrl+Shift+Пробел.**

## Настройки в `.env` (необязательно)

| Переменная | Что делает | По умолчанию |
|---|---|---|
| `AI_ACROBAT_DATA_DIR` | Где хранить файлы пользователей | `storage/ai-acrobat` рядом с корнем сайта |
| `AI_ACROBAT_MODEL` | Модель помощника | `GLOBAL_MODEL` |
| `AI_ACROBAT_OLLAMA_URL` | Адрес Ollama или шлюза | `OLLAMA_IP:OLLAMA_PORT` |
| `AI_ACROBAT_CONTEXT` | Размер контекста | `GLOBAL_MODEL_CONTEXT` или 32768 |
| `AI_ACROBAT_TIMEOUT` | Сколько секунд ждать модель | 180 |
| `AI_ACROBAT_MAX_TOKENS` | Длина ответа | 2048 |
| `AI_ACROBAT_AUTH_FILE` | Путь к `auth.php`, если папка лежит не в `/app/src/` | ищется автоматически |
| `AI_ACROBAT_ALLOW_ANON` | `1` — без входа (только для проверки!) | выключено |

### Откуда помощник берёт модель

Главный источник — файл **.env** вашей системы. Помощник находит его сам: рядом с папкой приложения
и выше по папкам (обычно это `.env` в корне сайта или уровнем выше). Если .env лежит в другом месте,
укажите путь в переменной `AI_ENV_FILE`. Значения из .env важнее переменных окружения процесса:
если сервер запущен со старыми переменными, а .env поменяли, работает то, что написано в .env.

Порядок поиска (берётся первое найденное):

| Что | Где ищется |
|---|---|
| Адрес сервера модели | `AI_ACROBAT_LLM_URL` → `LLM_URL`, `OLLAMA_URL`, `OPENAI_BASE_URL` (берутся как есть); без них — первый, который отвечает, из: `OLLAMA_IP` + `OLLAMA_PORT`, `OLLAMA_HOST` (без порта — `OLLAMA_PORT` или 11434, как у самой Ollama), `$url_ollama` из config.php системы, `127.0.0.1:11434` |
| Модель | `AI_ACROBAT_MODEL` → `GLOBAL_MODEL`, `LLM_MODEL`, `OLLAMA_MODEL`, `CHAT_MODEL`, `DEFAULT_MODEL` → `$global_model` из config.php → первая модель, которую отдаёт сам сервер |
| Размер контекста | `AI_ACROBAT_CONTEXT` → `GLOBAL_MODEL_CONTEXT`, `LLM_CONTEXT`, `OLLAMA_CTXSIZE` → `$ollama_ctxsize` → 32768 |
| Ключ (если шлюз его требует) | `AI_ACROBAT_API_KEY` → `LLM_API_KEY`, `OPENAI_API_KEY` |
| Протокол | `AI_ACROBAT_LLM_API` или `LLM_API` = `ollama` / `openai`; без них определяется сам |

- **Любой сервер:** работает и с Ollama, и с OpenAI-совместимыми серверами (vLLM, GLM, LM Studio и
  другие). Адрес с `/v1` на конце считается OpenAI-совместимым. Если у адреса нет `/api/chat`
  (как у Ollama), помощник сам пробует `/v1/chat/completions`.
- **Любая модель:** имя модели сверяется со списком моделей сервера. Если такой модели там нет,
  берётся подходящая из списка. Если шлюз принимает имена-псевдонимы, которых нет в его списке
  (например `chat`), поставьте `LLM_MODEL_CHECK=0`.
- Если сервер не умеет вызывать инструменты, помощник сам переходит на текстовый протокол вызовов.
- **Как проверить:** наведите мышь на строку «Модель: …» в шапке панели помощника. Там написано,
  какая модель используется и из какой строки .env она взята. То же показывает адрес
  `api/assistant.php` в браузере.


## Что пока не умеет

- Распознавание текста (OCR) внутри редактора в браузере пока не работает (и умеет только латиницу).
  Помощник читает сканы по снимку экрана, если модель принимает картинки.
